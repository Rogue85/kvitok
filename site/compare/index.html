Kvitok compared with other AI helpdesks

Most AI support products are built to close conversations on their own and charge for each resolution. Kvitok is built for support that changes data in your systems: the agent investigates in your backend and proposes, a person approves, and your backend executes. It is open source and runs on your servers with the model you choose.

Compared with Zendesk, Intercom Fin, Freshdesk Freddy AI, Chatwoot Captain and Zammad. Facts about other products come from their public websites and documentation as of November 2026.

What Kvitok does differently

Built for requests that change data

With points, refunds, coupons and cancelled orders a mistake costs money, so in Kvitok the agent proposes and a person decides.

The agent investigates in your backend

Your backend publishes read tools, actions and playbooks through a small signed HTTP protocol. The agent reads receipts, orders and balances with them, works out what went wrong and drafts a reply. Kvitok passes the customer from the ticket, so a prompt injection in an email cannot reach another customer's data.

A person approves every action

The agent proposes, an operator approves, and the backend checks the parameters again against the current state before executing. Operators correct the agent in a chat inside the ticket, and it changes only what the message is about. An automatic mode for safe cases is planned.

Your servers, your model, a known cost

There is no fee per resolution. Each workspace picks its provider, model and prices, so every agent run has a cost, and analytics breaks it down by day, department, model and ticket. A local model behind vLLM or Ollama keeps customer data on your network.

Changes are tested before customers see them

pnpm eval runs scenarios against a real model and reports what passed and what it cost. Over MCP, an external agent can replay past tickets with a changed configuration and compare the result with what operators did.

Your coding agent sets it up

Kvitok serves an MCP endpoint, and a Claude Code plugin ships in the repository. Claude Code, Cursor or another MCP client studies your backend, writes the protocol module and configures the workspace, then helps tune the agent from operators' corrections.

One installation, many projects

Kvitok knows nothing about your business. An online shop, a loyalty program and an internal tool each get a workspace with their own backend, departments, fields, routing rules and policy.

When something else fits better

Pick another tool if

You need live chat and a help center today

Zendesk, Intercom and Freshdesk are mature products with chat widgets, messaging channels, help centers and large integration catalogs. Kvitok takes email and API requests and has no chat widget yet.

The AI should answer customers on its own

Intercom Fin, Zendesk AI agents and Freddy AI are built to resolve conversations without a person. In Kvitok every reply and action waits for an operator.

You want an open-source omnichannel inbox

Chatwoot covers live chat, email, WhatsApp and social channels in one inbox, with the Captain assistant on top.

You want a mature open-source ticketing system

Zammad has years of production use, SLAs, a knowledge base and many integrations, plus AI summaries, a writing assistant and AI agents for routine tasks.

Questions

Frequently asked

Is Kvitok an open-source alternative to Zendesk?

For teams whose support work happens in their own backend, yes: Kvitok is a self-hosted helpdesk with tickets, departments, routing rules, custom fields, analytics and an AI agent that drafts replies and proposes actions. It is licensed under AGPL-3.0. It does not yet have a chat widget, a help center or SLAs.

Is there a self-hosted alternative to Intercom Fin?

Kvitok runs on your servers with a model you choose and charges nothing per resolution. Its agent reads your backend and proposes actions like Fin's procedures do, but an operator approves every action and reply before it reaches the customer.

Can I run the agent on my own or a local model?

Yes. Any OpenAI-compatible endpoint with tool calling works: OpenAI, OpenRouter, a LiteLLM proxy, vLLM or Ollama. Each workspace sets its own provider, model and prices.

How much does the AI cost to run?

What your model provider charges for the tokens. Kvitok records the cost of every agent run, shows it on the ticket and breaks it down in analytics, and pnpm eval reports the cost of each test run.

How does Kvitok connect to my backend?

Through the Support Action Protocol: a few signed HTTP endpoints for the manifest, customer lookup, the customer card, read tools and actions. The protocol package with a client and a conformance suite and the reference backend are MIT licensed. See docs/protocol.md.

Is Kvitok ready for production?

Not yet proven there. Kvitok is in early development, and until 1.0 a minor version may break compatibility. Try it on the coffee shop simulator, then connect a staging backend.
